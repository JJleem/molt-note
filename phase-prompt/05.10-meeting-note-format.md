# Phase 5.10 — Meeting Note Format (팀 회의록 형식)

> 상태: **확정 (2026-11-13).** 사용자가 "전부 다 개선"으로 범위를 정했고, 아래 Decisions는
> 그 위임에 따라 정한 기본값이다. PRODUCT-SPEC §9.5 · §11은 이미 이에 맞게 고쳤다.

## Goal

Meeting 모드 AI 노트가 **팀이 실제로 노션에 올리는 회의록 형식**
(`docs/MEETING-NOTE-FORMAT.md`)으로 나오게 한다. Markdown 내보내기와 Notion 전송도
같은 모양이어야 하며, **풀 전사를 노트 아래에 붙이지 않는 내보내기**가 가능해야 한다.

성공 기준:

> 2시간 안팎의 실제 회의 녹음 하나를 앱 안에서만 처리해, 사람이 손대지 않고 노션에
> 붙여 넣을 수 있는 회의록이 나온다 — 머리말 · 📌 안내 · 🔑 핵심 요약 · (해당 시) 🔁 지난
> 액션 아이템 · 주제별 섹션 · ✅ 액션 아이템(담당 · 📅) · 🔍 확인 필요.

## Why This Phase Exists

2026-11-13, 사용자가 팀 위클리 회의록 하나를 기준으로 지정하고 **앞으로의 회의 요약은 모두
이 형식에 맞춰야 한다**고 했다. 같은 날 1시간 53분 녹음의 앱 노트(현재 5섹션)를 그 형식으로
다시 써야 했고, 그 작업은 앱 밖에서 사람이 했다 — 앱이 할 수 없었기 때문이다.

현재 형식과의 차이는 표현이 아니라 **구조**다.

| | 현재 (§9.5 · ADR-0008 §7) | 기준 형식 |
| --- | --- | --- |
| 섹션 | Overview · Key Discussions · Decisions · Action Items · Open Questions | 핵심 요약 · 지난 액션 진행 · 주제별 N개 섹션 · 액션 아이템 · 확인 필요 |
| 항목 타입 | `string` / `string[]`만, 중첩 없음 (§7.3) | 주제 → 소제목 → 글머리표, 액션 아이템마다 담당·날짜·상태 |
| 담당·기한 | 스키마에 **일부러 없음** — 추출 능력 UNVERIFIED (§7.3) | 항목마다 있음. 모르면 `담당 확인` · `일정 확인` |
| 불확실성 표시 | 없음 | `STT상 ‘…’`, `(추정)`, 🔍 확인 필요, 반복 인식 구간 경고 |
| 내보내기 | 노트 아래 `## Transcript` 항상 붙음 (§11) | 풀 전사 없음 |

## Decisions

1. **PRODUCT-SPEC §9.5의 Meeting 출력은 `docs/MEETING-NOTE-FORMAT.md`다.** (Spec 반영 완료)
2. **Meeting 노트는 content schema v2로 간다.** 필드:

   ```text
   meetingTitle          string     회의명 (제목 [YYMMDD] <회의명>_회의록 에 쓰임)
   meetingKind           string     유형 한 줄 (회의 종류 + 흐름)
   attendees             string[]   들린 이름·호칭. 확정 못 하면 비워도 된다
   reliabilityNotice     string     📌 안내 문구 본문
   keySummary            string[]   🔑 핵심 요약 (5~7개 권장)
   previousActionItems   object     🔁 — done · changed · inProgress · noProgress · notMentioned
                                    각각 string[]. 전부 비면 섹션을 그리지 않는다
   topics                object[]   { title: string, groups: [{ heading: string, items: string[] }] }
                                    heading이 빈 문자열이면 소제목 없이 글머리표만
   actionItems           object[]   { task, detail, owner, due, period } — 전부 string
                                    owner 모르면 "담당 확인", due 모르면 "일정 확인"
                                    period = 기간 묶음 이름 (예: "이번 주 (~11/20 금)")
   needsConfirmation     string[]   🔍 확인 필요
   ```

   💬 · ⚠️ · `STT상 ‘…’` 같은 표시는 **항목 문자열 안에** 둔다 — 별도 필드로 만들지 않는다.
   날짜·시각(이벤트 시간, `[YYMMDD]`)은 **모델이 아니라 Recording에서** 채운다.
3. **ADR-0008 §7.3을 Meeting v2에 한해 개정한다** — 한 단계의 객체 중첩을 허용하고, 담당·기한을
   필드로 받는다. 근거: 모르면 `담당 확인` · `일정 확인`을 쓰게 강제하고, 추정은 `(추정)`으로
   드러내며, 사람이 🔍 확인 필요에서 검토한다. **추출 정확도 자체는 여전히 UNVERIFIED**이고
   개정 기록에 그렇게 적는다. Study · Summary는 v1 그대로.
4. **Meeting 프롬프트 입력에는 세그먼트 시각을 붙인다** (`[HH:MM:SS] 텍스트`). 확인 필요
   항목이 전사 시각을 가리킬 수 있어야 한다.
5. **반복 인식·깨진 구간은 모델이 전사에서 찾아 🔍에 적는다.** 기존 붕괴 판정(ADR-0007 §18)
   결과를 입력으로 넘기는 것은 DEFERRED.
6. **내보내기(§11)와 Notion 전송**: AI 노트가 있으면 Transcript 포함 여부를 고른다. Meeting
   노트의 기본값은 **포함하지 않음**. AI 노트가 없으면 Transcript는 언제나 들어간다 (INV-8).

## Required Outcome

1. Meeting 프롬프트·JSON schema가 Decisions 2의 필드를 요구한다. `promptVersion`이 바뀌고
   (`prompt.rs`의 해시 Gate), `CONTENT_SCHEMA_VERSION`이 올라간다.
2. **옛 노트(schema v1)는 그대로 읽히고 그대로 렌더된다.** `ai_notes`에는 UPDATE 경로가
   없으며 옛 노트를 고쳐 쓰지 않는다 (ADR-0008 §7.5).
3. 렌더러 셋 — 앱 화면(`src/screens/aiNoteView.ts`) · Markdown 내보내기 · Notion 전송 —
   이 같은 섹션을 같은 순서로 만든다.
4. 기준 형식의 "하지 않는 것"이 프롬프트 규칙에 들어간다 — 전사에 없는 결정·담당·날짜를
   만들지 않음, 불확실한 것은 표시로 드러냄.
5. ADR-0008에 §7.3 개정 기록이 남는다 (무엇이 바뀌었고 무엇이 여전히 UNVERIFIED인지).
6. 내보내기 화면에 Transcript 포함 선택이 생기고, Notion 전송도 같은 선택을 따른다.
7. **실제 provider 호출 없이** 검증한다: 지어낸 2시간 분량 회의의 v2 응답 fixture(약 25KB)가
   parse · 검증 · 저장 · 앱 렌더 · Markdown 렌더를 통과한다. 크기 상한
   (`MAX_ITEMS` · `MAX_ITEM_CHARS` · 출력 예약)이 이 크기를 거절하지 않는다.
8. 실제 녹음으로 끝까지 해 보는 것(생성 → 노션 붙여넣기)은 **Phase 이후 사람이 한다** —
   Gate가 구독 사용량을 쓰지 않게 한다.

## Known Constraints (구현 전에 알아야 할 것)

- **출력 예약이 작다.** `OUTPUT_RESERVE_TOKENS = 1536`(`src-tauri/src/ai/prompt.rs`).
  기준 형식으로 쓴 2시간 회의록은 약 26KB였다 — 이 예약으로는 담기지 않는다.
  `MAX_ITEM_CHARS` · `MAX_OVERVIEW_CHARS` · `MAX_ITEMS`도 다시 봐야 한다.
- **입력도 크다.** 2시간 전사는 약 126KB(2,639 세그먼트)이고, 문자/토큰 2:1 추정으로 약
  63K 토큰이다. 기본 context 16,384에는 들어가지 않는다. 같은 날 같은 녹음의 노트는
  `claude-cli`로 생성됐다 — 어떤 provider가 이 크기를 감당하는지는 provider별로 다르다.
- 기준 형식 원본은 실제 회의 내용이라 **저장소에 넣지 않는다** (GIT-WORKFLOW §7).
  테스트 fixture는 지어낸 회의로 만든다.

## Non-Goals

- Study · Summary 모드 변경
- 참석자 자동 식별(화자 분리)
- 노트 편집 UI
- 이전 회의록을 앱이 자동으로 불러와 🔁 섹션을 채우는 것 — 이번 Phase에서는 전사에 나온
  것만 쓴다
