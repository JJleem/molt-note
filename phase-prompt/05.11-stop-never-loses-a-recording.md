# Phase 5.11 — 정지는 녹음을 잃지 않는다 (Stop Never Drops a Finalized Recording)

> 상태: **확정 (2026-11-13).** 사용자 요청: "녹음하면 없어지는 것도 안 발생되게".

## Goal

**확정된 녹음 파일이 있으면, 정지는 언제나 그 녹음을 목록에 남긴다.** 녹음 도중에 무슨 일이
있었든(마이크 스트림 오류, 저장 지연으로 인한 일부 구간 유실) 그것은 **경고**로 함께 남고,
녹음이 목록에서 사라지는 이유가 되지 않는다.

## Why This Phase Exists

2026-11-13 11:12~13:05, 1시간 53분 회의 녹음이 정지 후 목록에서 사라졌다. 파일
(`capture-1794535932.wav`, 624MB)은 끝까지 정상 확정돼 있었고 DB 행만 없었다. 40초 뒤의
다음 녹음은 정상 저장됐다 — 앱도 DB도 살아 있었다. 앱 재시작 시 고아 녹음 입양
(2026-09-15에 만든 안전망)으로 되살렸다.

**코드에서 확인된 경로 (VERIFIED by reading):**

```text
system_capture: deliver()            큐(SAMPLE_QUEUE_CAPACITY = 256)가 한 번이라도 차면
                note_stream_error()  또는 스트림 오류가 한 번이라도 나면
  → interrupted 슬롯에 Failure 하나를 적어 둔다 (녹음은 계속된다)

정지 시:
capture::ActiveCapture::stop
  1. stop_device()   → interrupted 슬롯의 Failure를 Err로 돌려준다
  2. writer.join()   → 파일은 정상 확정된다
  3. stopped가 Err   → return Err   ← 여기서 끝
commands::Recorder::stop        → Err 전파 (finalized::verify도 건너뜀)
commands::finish_recording      → `recorder.stop()?` 에서 반환, save_capture에 가지 않는다
```

결과: **2시간 중 단 한 번의 버퍼 넘침이나 스트림 오류가 녹음 전체를 목록에서 빼 버린다.**
파일은 온전하다.

**이번 사건의 실제 트리거는 UNVERIFIED다** — 앱이 실패를 파일 로그로 남기지 않아, 큐 넘침인지
스트림 오류인지 알 수 없다. 녹음 중 실시간 전사(b0f31d9 이후)가 같이 돌았다면 부하로 큐가
찼을 가능성이 있다 (가설).

## Required Outcome

1. **정지 성공의 정의를 바꾼다.** 파일이 확정되고 `finalized::verify`를 통과하면 레코드를
   저장한다. 녹음 도중의 사건(interruption)은 정지를 실패로 만들지 않고, 결과에 **경고**로
   실려 사용자에게 보인다. ("녹음은 저장됐다. 다만 HH:MM 무렵 일부 구간이 유실됐을 수 있다")
2. 정지를 실패로 돌려야 하는 경우는 **파일이 확정되지 않았거나 verify를 통과하지 못한 경우**뿐이다.
   그때도 파일 경로를 담은 실패를 보낸다 (지금과 같음).
3. 경고는 레코드와 함께 남는다 — 앱을 다시 열어도 이 녹음에 그런 일이 있었다는 것을 볼 수 있다.
   (저장 형태는 Planner가 정한다. 기존 행을 고치는 migration이 필요하면 additive로)
4. **실패를 파일 로그로 남긴다.** 정지 실패·녹음 중 사건·DB 저장 실패를 앱 데이터 디렉터리의
   로그 파일에 시각과 함께 적는다. 다음 사건에서 원인을 추측하지 않아도 되게 한다.
   오디오·전사 내용은 로그에 쓰지 않는다 (INV-6 취지).
5. **녹음 도중의 사건을 언제 일어났는지 함께 기록한다** (녹음 시작 기준 경과 시간).
6. 고아 녹음 입양(시작 시)은 그대로 둔다 — 안전망이다. 다만 입양된 녹음의 `created_at`은
   입양 시각이 아니라 **파일 이름의 시작 시각**(`capture-<unix초>`)에서 가져온다.
7. 테스트: 가짜 SampleSource로 (a) 큐 넘침 (b) 스트림 오류 (c) 둘 다 없음 각각에서 정지하면
   레코드가 저장되고, (a)(b)는 경고가 실린다. (d) 파일 확정 실패면 레코드가 없고 경로를
   담은 실패가 온다.

## Non-Goals

- 큐 크기(256)를 바꾸는 것 — 근거가 생기기 전에는 바꾸지 않는다 (로그가 그 근거를 만든다).
- 실시간 전사 성능 개선.
- 유실된 구간을 복구하는 것.
