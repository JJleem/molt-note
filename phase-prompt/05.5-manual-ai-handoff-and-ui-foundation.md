`PRODUCT-SPEC.md` §21의 Phase Roadmap에는 **Phase 5.5가 없다.** Manual AI Handoff라는
개념도 Product Spec에 없다. 이 Phase는 운영자가 Phase 5와 Phase 6 사이에 넣기로 한 것이며,
**두 가지 제품 방향 변경**을 포함한다.

```text

```

## Goal

이 Phase의 성공 기준은 **두 개**다.

> 1. **AI Provider를 하나도 설정하지 않은 사용자가**, Recording Detail에서 Transcript를
>    외부 AI 채팅(ChatGPT · Claude · Gemini · 사내 AI 등 무엇이든)에 바로 붙여 넣을 수 있는
>    형태로 **복사하거나 파일로 꺼낼 수 있다.**
> 2. **화면 전체가 하나의 UI 기반 위에 선다** — 타이포그래피 · 여백 · 버튼 · 입력 · 상태 ·
>    빈 상태가 화면마다 제각각이지 않다.

두 번째가 첫 번째보다 덜 중요하지 않다. 다만 **최종 비주얼 리디자인이 아니다** —
나중의 UI/UX 다듬기가 딛고 설 바닥을 만드는 것까지다.

## Why This Phase Exists

Phase 4는 provider 추상화를 세웠고 Phase 5는 나가는 문을 만들었다. 그런데 **지금 이 제품에서
AI Note를 쓰려면 사용자가 Ollama를 설치하고 모델을 받아야 한다.** 대부분의 사람은 이미
쓰는 AI 채팅이 있고, 그쪽이 로컬 소형 모델보다 결과가 낫다.

INV-8은 "AI가 없어도 제품이 동작한다"를 요구했다. 이 Phase는 거기서 한 걸음 더 간다 —
**AI Provider가 없어도 AI의 값을 얻을 수 있게 한다.**

동시에, Final Integration에서 사람이 앱을 처음 실제로 보게 된다. 그 전에 화면이 서로 다른
규칙으로 그려져 있으면 그때 보이는 것은 제품이 아니라 조각들이다.

                                 --hairline · --selected

새 토큰을 더할 때 dark 블록에도 함께 정의하는 것으로 충분하다. 테마 시스템 프로젝트로
번지게 하지 않는다.

## Required Outcome

### A. Manual AI Handoff

1. **Copy AI Prompt** — 고른 mode(Meeting · Study · Summary)에 맞는 프롬프트를 만든다.
   `ai::prompt`의 기존 프롬프트를 재사용하고 두 번째 세트를 만들지 않는다.
   출력이 **구조화된 Markdown**으로 오도록 요청하는 문구를 포함한다.
   **어떤 벤더에도 맞추지 않는다** — ChatGPT·Claude·Gemini·Ollama 어느 이름도 들어가지 않는다.

2. **Copy Transcript** — 현재 성공한 Transcript를 깨끗하고 예측 가능한 형태로 복사한다.
   timestamp 정보가 유용한 곳에서는 보존한다.

3. **Export for AI** — Phase 5의 중립 export 구조를 **재사용해서** AI에게 줄 문서 하나를
   만든다. 외부 AI 채팅이 요청을 이해하기에 충분한 맥락(모드 · 지시 · 메타데이터 · Transcript)을
   담는다. **정확한 형식은 이 Phase가 정한다** — 아래는 개념 예시일 뿐 요구 형식이 아니다.

   ```md
   # Molt Note AI Request
   ## Mode
   ## Instructions
   ## Recording
   ## Transcript
   ### 00:00:03
   ```

   병렬 export 시스템을 만들지 않는다. `export::Document`에서 갈라지는 renderer 하나가 는다.

4. **순수 계층에서 테스트된다** — 프롬프트 생성 · AI-ready 문서 생성 · timestamp 표현이
   결정론적 순수 함수이고, clipboard·파일·네트워크와 분리돼 있다 (§18).

### B. Manual Handoff 불변 (전부 자동 테스트로 고정한다)

```text
MH-1  AI Provider가 하나도 설정되지 않아도 동작한다
MH-2  Ollama를 요구하지 않는다
MH-3  네트워크로 자동 전송하지 않는다 — 복사·export는 사용자의 로컬 행동이다
MH-4  audio 바이트도 audio 경로도 산출물에 들어가지 않는다
MH-5  현재 성공한 Transcript를 쓴다 (§7.2) — 실패했거나 대체된 옛 version을 조용히 고르지 않는다
MH-6  vendor 중립이다 — ChatGPT/Claude/Gemini 고유 schema가 core/domain에 들어가지 않는다
MH-7  복사·export 실패가 Recording · Transcript · AINote · 기존 export를 훼손하지 않는다
MH-8  기존 Connected Provider 생성 경로가 그대로 살아 있다
```

5. **clipboard 경계** — 기존 아키텍처와 일관된 작은 IPC/platform 경계 하나.
   실패가 보이고 재시도 가능하다. React 컴포넌트에 clipboard 호출을 흩지 않는다.

6. **AI Note 화면의 위계를 바꾼다** — provider 부재가 "설정하라는 요구"가 아니라
   **정상적으로 지원되는 상태**로 보인다.

   ```text
   AI Note
     자동으로 만들기   [ 연결된 provider로 생성 ]
     또는
     내 AI로 하기      [ Copy AI Prompt ] [ Copy Transcript ] [ Export for AI ]
   ```

   provider가 없어도 아래 줄은 **완전히 쓸 수 있다.** 공격적인 설정 유도를 넣지 않는다.

### C. Ollama 재배치

7. **Ollama를 지우지 않는다.** 유지가 적극적으로 해로운 경우가 아니면 **삭제가 아니라
   재배치**다. Settings에서 `선택적 · 로컬 · 고급`에 해당하는 위치로 옮기고, 제품 언어를
   기존 표현과 일관되게 맞춘다. Phase 4의 provider 추상화는 그대로 둔다.

8. **새 cloud provider를 붙이지 않는다** — OpenAI · Claude · Gemini · Codex 어느 것도.
   그것은 미래의 provider 작업이다 (`PRODUCT-SPEC` §16).

### D. UI Foundation

9. **작은 내부 기반**을 만든다. 큰 서드파티 디자인 시스템을 들이지 않는다 —
   현재 의존성이 그것을 강하게 정당화하지 않는다. **기존 것을 먼저 재사용한다** (R-1 · R-2).

   - **타이포그래피**: `page title · section title · body · secondary · caption` 위계.
     화면마다 임의의 font-size를 흩지 않는다 (현재 17곳).
   - **여백**: 작은 일관 스케일 (예: 4 · 8 · 12 · 16 · 24 · 32 — 정확한 값은 구현 결정).
   - **radius**: 이미 5px 하나로 통일돼 있다. **바꿀 이유가 없으면 그대로 둔다.**
   - **표면 위계**: 여백 · 타이포 · 옅은 배경 차이 · 최소한의 구분선.
     무거운 테두리와 과한 카드를 쓰지 않는다.
   - **버튼**: `Primary · Secondary · Ghost/Text` + 정말 필요한 곳의 `Danger`.
     한 화면에 분명한 primary 하나.
   - **입력**: text input · select · toggle · 검증/오류 표현의 일관성.
   - **상태**: `idle · working · success · warning · error · disabled` 시각 규칙.
   - **빈 상태**: 데이터가 없을 때 고장난 것처럼 보이지 않는다 —
     녹음 없음 · transcript 없음 · AI Note 없음 · provider 없음 · Notion 미설정.
   - **로딩**: 오래 걸리는 동작이 얼어붙은 것처럼 보이지 않는다.

10. **주요 화면에 적용한다** — Recordings(홈) · Recording · Recording Detail · Settings.
    - 목록의 모든 행을 무거운 카드로 만들지 않는다.
    - 녹음 화면은 **상태와 주 조작(Record/Pause/Resume/Stop)이 지배한다.**
      보기 좋으라고 기능적 명확성을 희생하지 않는다.
    - Detail의 내용 위계가 이해된다. **탭을 다른 것으로 갈아엎지 않는다** (R-2).
    - Settings는 단순한 그룹 목록. 설정마다 장식 카드를 두지 않는다.
      개념 그룹: `General · Transcription · AI(연결된 provider · Ollama—로컬/선택) · Notion · About`.

11. **시각 방향**: 깨끗함 · 밝음 · 차분함 · 높은 정보 명료도 · 넉넉한 여백 · 최소 장식.
    중립 표면. accent는 **주 동작 · 활성 네비게이션 · 의미 있는 상태 강조**에만.
    경쟁하는 색을 여럿 쓰지 않는다.
    **gradient · glassmorphism · 과한 그림자 · 장식적 애니메이션을 넣지 않는다.**
    애니메이션은 상태 전이를 분명하게 할 때만.

    > Toss는 **정보 위계와 단순함의 질적 참고**로만 쓴다.
    > 복제하지 않고, 브랜드 자산을 가져오지 않고, Toss 고유의 시각 정체성을 들이지 않는다.
    > 흉내가 아니라 원칙을 본다.

12. **접근성 기준선** (R-5): 키보드로 조작 가능 · **보이는 focus 상태** · 컨트롤에 레이블 ·
    합리적 대비 · **색만으로 상태를 말하지 않는다** · disabled 구분 가능 ·
    semantic button/input. 전용 접근성 Phase로 만들지 않는다.

### E. 아키텍처 제약

13. **기존 경계를 지킨다.** UI 구현을 쉽게 하려고 비즈니스 로직을 React 컴포넌트로 옮기지
    않는다 (R-2의 규약). Manual AI 생성은 테스트 가능한 순수/domain 또는 export 경계를 갖는다.
    clipboard · 파일시스템 · URL 열기는 **capability 경계이지 domain 로직이 아니다.**
    core/domain에 벤더 고유 개념을 만들지 않는다.

14. build · lint · test Gate가 전부 통과한다. **Phase 종료 시 저장소 전체에 세 Gate를 돌린다.**

자동 로그인 · 브라우저 자동화 · 메시지 주입 · 자동 파일 업로드 · 스크래핑 ·
비공식 세션/토큰 접근을 **시도하지 않는다.**
본질은 딥링크 자동화가 아니라 **가져갈 수 있는 AI-ready 내용**이다.

## Important Rules

- **Phase 4의 provider 추상화를 삭제하지 않는다.** Manual Handoff가 생겼다는 이유만으로.
- **Ollama adapter를 삭제하지 않는다.** 재배치가 우선이다.
- 자동 테스트가 실제 provider · 실제 Notion · 실제 자격증명 저장소를 건드리지 않는다.
- **픽셀/스크린샷 비교 테스트를 넣지 않는다.** UI 테스트는 중요한 동작을 검증한다.
- **Git commit / push는 이 Phase의 작업이 아니다.** Phase commit은 완료·검증 후 운영자가 한다
  (`docs/GIT-WORKFLOW.md`). Worker가 commit하면 Gate·Verifier가 묶인 subject fingerprint가
  실행 도중 흔들린다.

## Verification Boundary

- provider가 하나도 없는 상태에서 Copy AI Prompt · Copy Transcript · Export for AI가
  **전부 동작한다** — 테스트로 확인된다 (MH-1 · MH-2).
- AI-ready 산출물에 audio 경로도 바이트도 없다 (MH-4) — 소스/타입 수준에서 확인된다.
- 현재 성공한 Transcript가 쓰인다 (MH-5) — 옛 version을 고르는 경로가 없다.
- 산출물에 벤더 이름·고유 schema가 없다 (MH-6).
- 복사·export 실패가 local data를 훼손하지 않는다 (MH-7).
- 기존 Connected Provider 생성이 그대로 동작한다 (MH-8) — 기존 테스트가 계속 통과한다.
- 프롬프트가 `ai::prompt`를 재사용하며 두 번째 프롬프트 세트가 생기지 않았다.
- 렌더링 로직이 복제되지 않았다 — `export::Document`에서 갈라진다.
- clipboard가 하나의 경계 뒤에 있고 React 컴포넌트에 흩어져 있지 않다.
- 타입/여백 스케일이 정의되고 주요 화면이 그것을 쓴다 — 임의 font-size가 줄어든다.
- 보이는 focus 상태가 존재한다.
- 색만으로 상태를 말하는 곳이 없다.
- dark mode 장치가 깨지지 않았다 — 새 토큰이 dark 블록에도 정의돼 있다.
- 픽셀 비교 테스트가 추가되지 않았다.
- build / lint / test Gate가 green이다.

### Human Review 항목

- 화면이 실제로 **차분하고 읽기 쉬운가** — 자동으로 판정할 수 없다
- Manual AI Handoff로 받은 결과가 **실제 외부 AI 채팅에서 쓸 만한가**
- Ollama가 "선택적·고급"으로 읽히는가, 아니면 여전히 기본처럼 보이는가
