## 0. 이 다섯은 **자동 Gate가 판정할 수 없다** — 이 문서가 존재하는 이유

`phase-prompt/05.6`이 Human Review 항목을 적으면서 그 성격을 함께 못박았다:

> *"이들은 **주관적 Human Review 항목이지 자동 Gate로 판정할 수 있는 것이 아니다.**"*

**`build` · `lint` · `test` 세 Gate 중 어느 것도 아래 다섯에 답하지 못한다.** 이유가 항목마다
다르므로 각각 적는다 — 자동 검증이 무엇을 이미 했는지도 함께 적어, **자동으로 이미 확인된 것을
사람이 다시 세지 않게** 한다.

| # | 항목 | 자동 검증이 이미 하는 것 | **왜 Gate가 판정할 수 없는가** |
| --- | --- | --- | --- |
| **HR-1** | **한국어 회의가 읽을 만하게 전사되는가** | 언어 선택이 엔진 경계까지 값으로 도달한다 · 고르지 않으면 감지가 켜진다 · 고르면 그 언어가 지정된다 · 설정이 왕복하고 다른 설정 저장에 지워지지 않는다 [E3] | **자동 검증에는 실제 모델도 실제 오디오도 없다** — 언제나 `StubEngine`으로 돈다 (`PRODUCT-SPEC` §18). **stub은 한국어가 한국어로 들렸는지를 알 수 없다** (`ADR-0007` §17.3이 기록한 Gate의 경계 그대로다) |
| **HR-2** | **`ggml-base`로 충분한가, 더 큰 모델이 필요한가** (`A-TRANS-001`의 실질적 답) | **아무것도 하지 못한다.** 모델은 저장소에 없고 Gate는 모델을 두지 않는다 | **"이 전사가 읽을 만한가"는 사람의 귀로만 답한다.** Phase 5.6은 *여러 모델을 쓸 수 있게* 만들었을 뿐 **어느 것이 충분한지 판정하지 않기로 했다** (`ADR-0007` §17.4) |
| **HR-3** | **Metal 활성화 전후로 체감이 달라지는가** | `metal` feature가 빌드 산출물을 실제로 바꿨다는 것(`GGML_METAL` OFF→ON · `libggml-metal.a` · 링크된 바이너리의 심볼)까지 [E1 · `ADR-0007` §19.2] | **"켜졌다"와 "빨라졌다"는 다른 명제다.** 이 저장소는 전사 속도를 **한 번도 측정한 적이 없고**(§19.2), 런타임에 GPU가 실제로 잡히는지도 확인하지 않았다. 체감은 사람이 앱을 쓰면서만 생긴다 |
| **HR-4** | **내보낸 파일을 실제로 열 수 있는가** | 열리는 대상이 앱의 `exports/` 아래 파일로 제한된다 · `..`·symlink·디렉터리·빈 경로가 거절된다 · OS 호출이 `platform/` 안에만 있다 · 경로 문자열이 사라지지 않았다 [E3] | **`open -R`도 `explorer /select,`도 이 저장소의 어떤 Run에서도 실행된 적이 없다** (`ADR-0009` §16.2의 [E4]). 자동 테스트는 언제나 double을 쓴다 — **부르면 검사가 도는 동안 창이 열리기 때문에** 그것이 의도된 설계다. **창이 실제로 뜨는지는 사람만 본다** |
| **HR-5** | **긴 회의의 handoff를 실제로 AI 채팅에 넣을 수 있는가** | 크기가 값으로 나온다 · 나눔이 결정적이고 무손실이며 순서를 보존한다 · 각 조각이 자기 자리를 말한다 · 잘린 결과를 온전하다고 말하는 상태가 없다 [E3] | **예산 40,000 B가 실제 채팅에서 맞는 크기인지는 UNVERIFIED다** — 어떤 채팅의 확인된 한도도 아니고 이 앱이 고른 값이다 (`ADR-0010` §12.8.2). **조각을 순서대로 붙여 넣는 것이 사람에게 쓸 만한 경험인지**는 값으로 판정되지 않는다 |

**HR-2는 나머지 넷과 무게가 다르다.** 넷은 이 Phase가 만든 것의 판정이고, **HR-2는 이 Phase가
닫지 못한 가정(`A-TRANS-001`)의 판정**이다. §7에 그 구분을 다시 적는다.

## 0.1 표기 — 확인한 것과 확인하지 못한 것을 섞지 않는다

| 표기 | 뜻 |
| --- | --- |
| **[E1] 저장소에서 직접 확인** | 이 문서를 쓴 Run이 저장소의 실제 파일을 읽어 확인했다. 화면 문구 · 상수 · 경로 · 필드 이름이 여기 해당한다 |
| **[E2] 저장소 문서의 기록** | `phase-prompt/05.6` · `05.7` · ADR-0007 §17~§19 · ADR-0009 §16 · ADR-0010 §12.8 · 앞선 Task의 evidence가 기록한 값 |
| **[E3] Runtime이 목격한 Gate 실행** | **이 문서를 쓴 Run의 실행이 아니다.** 이 Phase의 마지막 엔지니어링 Task(**TASK-074**)를 돌릴 때 **Runtime이 직접 실행한** `build` · `lint` · `test` Gate 결과다 — 셋 다 `"status": "PASS"` · `"exit_code": 0`이며, 그 `test` 로그가 vitest **586**(`Tests 586 passed`)과 Rust **885**(`test result: ok. N passed` 35줄의 합)를 적고 있다. 원본은 Runtime 소유 경로 `.loop-local/runs/RUN-20260907T062848Z-TASK-074/`의 `gate-report.json` · `gates/test/stdout.log`이고, **이 Task는 그것을 읽기만 했다** |
| **[E4] UNVERIFIED** | 이 Run에서 확인하지 못했다. **실행해 보면 드러난다 — 확인한 것처럼 적지 않는다** |

**이 Run에는 앱 실행도, 실제 모델 파일도, 실제 오디오도, AI 채팅도 없었다.** 그러므로:

- **아래에 인용된 화면 문구 · 상수 · 경로는 전부 [E1]이다.** 출처가 함께 적혀 있다.
- **그 문구가 실제 화면에서 어떻게 보이는지, 실제 전사가 무엇을 내는지, 실제 채팅이 무엇을
  받아들이는지는 전부 [E4]다.**

> ⚠️ **[E3]의 수치를 이 Run이 만들지 않았다는 것을 여기서 못박는다.**
> TASK-075는 문서 전용 Task이고 **결정론적 Gate를 선언하지 않았다** (`stop_condition`의
> `gates: (none enabled)`). 그래서 **Runtime이 이 Run에 대해 목격한 Gate 실행은 없다.**
> 위 vitest 586 · Rust 885는 **TASK-074의 Run에서 Runtime이 스스로 돌려 남긴 로그의 값**이고,
> 그것이 오늘의 저장소에도 서는 이유는 하나뿐이다 — **TASK-074 이후 이 Phase가 바꾼 것이
> `docs/` 아래뿐이고, 세 Gate 중 어느 것도 `docs/`를 읽지 않는다.**
> 이 Run이 참고로 돌린 `loopctl self-check`는 스스로 *"advisory only — not a gate report"* 라고
> 말하는 실행이며, **그 실행을 근거로 이 문서에 새 수치를 넣지 않았다.**

## 2. 준비물

### 2.1 앱을 실행한다 [E1]

저장소 루트에서:

```bash
npm install          # 처음 한 번
npm run tauri dev
```

> ⚠️ **첫 빌드가 whisper.cpp 컴파일을 포함한다** — Metal이 켜진 뒤로는 더욱 그렇다
> (`ADR-0007` §4.3 · §17.2.4). 오래 걸려도 멈춘 것이 아니다.

앱 데이터 디렉터리는 추측하지 않고 DB 파일로 확정한다 [E1 · `platform/app_data_dir.rs`]:

```bash
find "$HOME/Library/Application Support" -maxdepth 3 -name molt-note.db 2>/dev/null
APP_DATA="$HOME/Library/Application Support/com.moltnote.app"   # find가 알려준 값으로 바꾼다
```

`exports/`는 그 아래에 있다 [E1 · `AppDataDirectory::exports_dir()`]. **HR-4가 재는 것이
바로 이 자리에 사람이 도달할 수 있는가다** — 그러니 **위 `find`로 알아낸 경로를 미리 Finder에
띄워 두지 않는다.** 그러면 이 항목이 무효가 된다.

### 2.2 모델 파일 — HR-1 · HR-2 · HR-3에 필요하다

| 무엇 | 어떻게 | 확인 |
| --- | --- | --- |
| **모델을 둘 자리** | `"$APP_DATA/models/"`. **앱이 이 디렉터리를 만들지 않는다** — 사람이 만든다 (`ADR-0007` §16.2) | `mkdir -p "$APP_DATA/models"` |
| **모델 파일** | Whisper `ggml` 모델을 그 아래에 둔다. **HR-2를 위해 최소 둘이 필요하다** — `ggml-base.bin`과 더 큰 것 하나(예: `ggml-large-v3-turbo.bin`) | 설정하지 않으면 화면이 말한다: *"No transcription model is set, so recordings cannot be transcribed right now."* [E1 · `settingsView.ts`] |
| **설정에 넣는 값** | Settings → Transcription의 모델 칸에 **파일 이름**을 넣는다. 절대 경로도 받는다 (`transcription::model`이 그것을 해석하는 유일한 자리다) | 어떤 모델로 만들어졌는지는 Transcript의 `model`에 남는다 [E1] |

### 2.3 전사 언어 설정 — 이 Phase가 만든 것 [E1 · `settingsView.ts`]

Settings → Transcription에 **언어 칸**이 있다. 화면이 두 상태를 말한다:

```text
비워 둔다        "No language is set, so the language of each recording is detected
                  automatically. This is a normal setting, not something left undone."

코드를 넣는다     "Recordings are transcribed as "ko", so the language is not detected."

칸 아래의 안내    "Leave this empty to keep detecting the language, or enter a language code
                  (for example ko or en) to transcribe every recording in that language."
```

**비어 있는 것이 오류가 아니라 자동 감지라는 것**이 화면의 말로 드러나야 한다 — 그것이
이 Phase의 결정이었다 (`ADR-0007` §17.1.4-1). **§3.1이 그것을 첫 항목으로 본다.**

### 2.4 녹음 — 무엇을 녹음하는가

| 조건 | 값 | 왜 |
| --- | --- | --- |
| **입력 레벨** | 녹음 화면의 레벨 표시가 **"쓸 만함"인 상태에서 시작하고 끝까지 유지한다** | Phase 5.7이 만든 표시다. **낮은 레벨로 녹음하면 HR-1이 무효가 된다** — 2026-09-07이 그렇게 무너졌고, 그것은 언어 문제가 아니었다 (`ADR-0007` §18) |

| **내용** | **실제 사람의 한국어 말.** 여러 사람이면 더 좋다 | 화자 분리는 이 제품의 범위 밖이지만(`PRODUCT-SPEC` §15) 실사용의 모양이 그렇다 |

### 2.5 자동 검증이 이미 본 것 — 사람이 다시 세지 않아도 되는 것 [E3]

**이 문서를 쓴 Run이 돌린 것이 아니다** (§0.1). 아래는 이 Phase의 마지막 엔지니어링
Task(**TASK-074**)를 돌릴 때 **Runtime이 직접 실행한** Gate 결과이며, 원본은 Runtime 소유
경로에 그대로 있다:

```text
.loop-local/runs/RUN-20260907T062848Z-TASK-074/

build  PASS  exit=0     gate-report.json
lint   PASS  exit=0     gate-report.json
test   PASS  exit=0     gates/test/stdout.log — vitest 586 · Rust 885
```

**TASK-075(이 문서를 쓴 Task)는 Gate를 선언하지 않았고, Runtime이 목격한 실행도 없다.**
그 뒤로 바뀐 것이 `docs/` 아래뿐이므로 위 결과가 오늘의 저장소에도 그대로 선다.

이 셋이 통과했다는 사실은 **아래 다섯 중 어느 것도 판정하지 않는다** (§0).

## 3. HR-1 — 한국어 회의가 읽을 만하게 전사되는가

**자동 테스트가 이미 본 것을 다시 보지 않는다** [E3] — 언어가 엔진 경계까지 도달한다는 것,
고르지 않으면 감지가 켜진다는 것, 설정이 왕복한다는 것은
`src-tauri/tests/transcription_language.rs`와 `tests/transcription-and-reach-invariants.test.ts`가
판정한다.

**여기서 보는 것은 그 경로가 실제 한국어 음성에 대해 무엇을 내는가다.**

### 3.1 설정이 말을 하는가 (전사 전에 본다)

| # | 확인 | 기대 [E1 · `settingsView.ts` · `SettingsScreen.tsx`] |
| --- | --- | --- |
| **1a** | 언어 칸을 **비운 채로** 저장한다 | 화면이 *"…detected automatically. This is a normal setting, not something left undone."* 라고 말한다. **"설정되지 않음" 같은 오류 표현이면 FAIL이다** |
| **1b** | `ko`를 넣고 저장한다 | *"Recordings are transcribed as \"ko\", so the language is not detected."* |
| **1c** | **다른 설정 하나만 바꿔 저장한다** (예: 모델) | **언어 값이 그대로 남아 있는가.** 사라지면 FAIL — 폼을 지나지 않는 값이 조용히 `null`이 되는 회귀이며, 자동 테스트가 그것을 막고 있지만 화면 조작으로 한 번 확인한다 |
| **1d** | 앱을 껐다 켠다 | 언어 값이 그대로다 |

### 3.2 ★ 전사한다 — 이 Phase의 이유

§2.4의 조건으로 녹음한 뒤 Recording Detail에서 전사를 시작한다.

| # | 확인 | 기대 |
| --- | --- | --- |
| **1e** | **결과에 한글이 있는가** | 2026-09-05에는 **한글이 나온 줄이 0이었다** [E2 · `ADR-0007` §17.1.1]. 이 항목이 이 Phase의 최소 성적표다 |
| **1f** | Transcript 탭의 `language` 자리 | 엔진이 보고한 값이다 — `ko`가 보이면 엔진이 한국어로 들었다는 뜻이다. **비어 있어도 그것은 버그가 아니다**(엔진이 말하지 못했다는 뜻이다 · `ADR-0007` §17.1.4-3). 보이는 그대로 §8.1에 적는다 |
| **1g** | **회의에서 실제로 나온 말이 거기 있는가** | 기억나는 문장 서넛을 찾아본다 |
| **1h** | **문장의 흐름을 따라갈 수 있는가** | 화자 이름은 없다(범위 밖). 흐름을 따라갈 수 있으면 된다 |
| **1i** | 같은 문장이 되풀이되지 않는가 | 2026-09-05는 상위 2문장이 전체의 86.7%였다 [E2]. **되풀이가 보이면 그 문장과 대략의 비율을 적는다** |
| **1j** | 학습 데이터 잔재(자막 크레딧 등)가 섞여 있는가 | 있으면 **몇 개, 어디에** 있는지 적는다 |
| **1k** | timestamp가 실제 시각과 맞는가 | 아무 segment나 골라 그 시각의 오디오를 재생해 본다 |
| **1l** | **★ 이 전사를 실제로 쓰겠는가** | AI 채팅에 넣거나, Markdown으로 내보내거나, 그냥 읽거나. **"쓰지는 않겠다"면 FAIL이다** — 이것이 HR-1의 판정이다 |

### 3.3 붕괴로 막혔다면 — 그것도 기록이다

1o  붕괴했다면 입력 레벨을 먼저 의심한다 (docs/PHASE-5.7-HUMAN-REVIEW.md §3 · §6)

## 4. HR-3 — Metal 활성화 전후로 체감이 달라지는가

> **순서를 HR-2보다 앞에 둔 이유가 있다.** HR-3의 before 값을 만들려면 **빌드를 한 번 되돌려야
> 하고**, 그것은 §3의 녹음 파일이 이미 있어야 할 수 있는 일이기 때문이다. HR-2는 그 뒤에 한다.

### 4.1 지금 무엇이 기록되는가 [E1]

Phase 5.6이 만든 것은 **비교할 값이 남는 자리**다 (`ADR-0007` §19.3).

```text
Transcript 탭의 provenance 아래 한 줄        "Transcribed in <시간>"
        ↑ 문장은 Rust가 만든다 (transcriptionLabel). 화면은 밀리초를 나누지 않는다
        ↑ 값이 없는 옛 Transcript에서는 **그 줄이 아예 없다** — "0:00"이라고 말하지 않는다
```

DB에서도 직접 읽을 수 있다 [E1 · migration 10]:

```bash
sqlite3 "$APP_DATA/molt-note.db" \
  "SELECT id, model, language, transcription_ms FROM transcripts ORDER BY created_at;"
```

| # | 확인 | 기대 |
| --- | --- | --- |
| **3a** | §3.2의 성공한 전사에 **그 줄이 있는가** | 있어야 한다 |
| **3b** | 이 열이 생기기 전에 만들어진 옛 Transcript | `transcription_ms`가 `NULL`이고 **화면에 그 줄이 없다.** "0:00"으로 보이면 FAIL이다 |
| **3c** | 붕괴로 막힌 전사 | **Transcript가 없으므로 시간도 없다.** 실패한 시도의 시간은 남지 않는다 (`ADR-0007` §19.3) — 버그가 아니다 |

### 4.2 ★ before를 만드는 방법 — **저장된 before 값이 없다**

**이것을 먼저 분명히 적는다.**

```text
[관측된 사실]  전사 소요 시간을 기록하는 열(migration 10)은 Metal을 켠 것과 **같은 Phase**에
               생겼다. 그러므로 **Metal이 꺼져 있던 시절의 소요 시간은 저장소 어디에도 없다.**

[관측된 사실]  2026-09-07 실행의 4.30분은 **붕괴한 디코딩**의 소요 시간이다 (같은 문장 102회).
               2026-09-05의 26분도 마찬가지다 (같은 문장 1,063회).
               **둘 다 정상 디코딩의 속도가 아니므로 기준값으로 쓰지 않는다**
               (phase-prompt/05.6 R-6의 명시적 단서 · ADR-0007 §17.2.3).

[미검증]       그러므로 "Metal 전"의 값은 **지금 만들어야만 존재한다.**
```

**before를 만드는 유일한 방법 — 한 번 되돌렸다가 되돌린다:**

```bash
# 1. Metal을 끈다 — src-tauri/Cargo.toml 의 한 줄만 바꾼다
#    whisper-rs = { version = "0.16", features = ["metal"] }
#    → whisper-rs = "0.16"
#
# 2. 앱을 다시 빌드해 실행한다.  ⚠️ whisper.cpp가 재컴파일된다 (ADR-0007 §4.3)
#
# 3. §3.2와 **같은 녹음 · 같은 모델 · 같은 언어**로 다시 전사하고
#    "Transcribed in …" 값을 적는다                            ← 이것이 before다
#
# 4. Cargo.toml 을 원래대로 되돌리고 다시 빌드한다
#
# 5. 또 같은 조건으로 전사하고 값을 적는다                       ← 이것이 after다
```

| 지켜야 하는 것 | 왜 |
| --- | --- |
| **같은 오디오 · 같은 모델 · 같은 언어** | 하나라도 다르면 두 값이 무엇의 차이인지 말할 수 없다. 2026-09-05의 관측이 쓸 수 없었던 이유가 정확히 그것이다 — **언어 · Metal · 청크 분할 셋이 함께 바뀌었다** [E2 · `ADR-0007` §17.2.3] |
| **다른 무거운 작업을 함께 돌리지 않는다** | 이 값은 벽시계가 아니라 단조 시계로 잰 실제 소요 시간이지만, 기기가 바쁘면 그대로 늘어난다 |
| **되돌리는 것을 잊지 않는다** | 4단계를 건너뛰면 저장소가 Spec §14.4와 다시 어긋난다 (`ADR-0007` §17.2.1) |

> **[E4] 이 Run은 위 절차를 실행하지 못했다.** 그러므로 **"Metal이 빠르다"고도 "차이가 없다"고도
> 이 문서에 적지 않는다.** §8.3의 두 칸이 채워지기 전까지 그 문장은 존재하지 않는다.

### 4.3 그래서 체감이 달라지는가 — 사람만 답하는 자리

| # | 질문 | 기대 |
| --- | --- | --- |
| **3d** | before / after 두 값을 얻었는가 | §8.3의 두 칸. **얻지 못했으면 `미실행`이지 "차이 없음"이 아니다** |
| **3e** | **★ 기다리는 동안 느낌이 다른가** | 숫자가 아니라 인상이다. *"그새 딴 일을 하러 갔다"* 와 *"기다릴 만했다"* 는 다른 사실이다 |
| **3f** | 여전히 화면에 아무 변화가 없어 답답한가 | **진행률은 이 Phase가 만들지 않았다** (`phase-prompt/05.6` R-6). 답답하면 그 사실을 적는다 — 다음 Phase 후보의 근거가 된다 |
| **3g** | 전사 중에 앱이 죽지 않았는가 | in-process abort는 `ADR-0007` §4.3이 감수한 대가이며 **아직 관측된 적이 없다.** 일어나면 그것은 중요한 첫 관측이다 |

## 5. HR-2 — ★ `ggml-base`로 충분한가, 더 큰 모델이 필요한가

> **이것이 `A-TRANS-001`의 실질적 답이다.** 나머지 넷이 전부 PASS여도 **이것이 열려 있는 동안
> `A-TRANS-001`은 닫히지 않는다** (§7).

### 5.1 무엇을 비교하는가

**같은 오디오를 모델만 바꿔 전사한다.** 다른 것은 하나도 바꾸지 않는다.

```text
같은 녹음 (§2.4의 것) · 같은 언어 설정 `ko` · 같은 빌드
    ├─ ggml-base.bin                 ← 2026-09-05에 쓰인 모델 [E2]
    └─ ggml-large-v3-turbo.bin       ← 2026-09-07에 쓰인 모델 [E2]
```

**재전사는 덮어쓰기가 아니라 추가다** (`PRODUCT-SPEC` §7.1 · INV-2) — 두 결과가 Transcript 탭에
나란히 남으므로 지우지 않고 비교할 수 있다.

### 5.2 무엇을 재는가

**9/5 · 9/7과 같은 방법으로 잰다** — 그래야 나란히 놓인다 [E2 · `ADR-0007` §18.1].

```text
총 segment 수 · 문장 n · 고유 u (u/n) · 최다 반복 r (r/n) · 저장된 상태(done / failed) ·
전사 소요 시간("Transcribed in …") · 모델 · 사람의 판정
```

### 5.3 그래서 무엇이 충분한가 — 수치가 답하지 않는 자리

| # | 질문 | 기대 |
| --- | --- | --- |
| **2a** | `base`의 결과가 **읽을 만한가** | §3.2의 1g~1l을 그 결과에 대해 다시 묻는다 |
| **2b** | 더 큰 모델의 결과가 **눈에 띄게 나은가** | *"조금 낫다"* 와 *"이제야 쓸 만하다"* 는 다른 답이다. 어느 쪽인지 적는다 |
| **2c** | **차이가 어디서 나는가** | 고유명사 · 숫자 · 영어 섞인 구간 · 겹쳐 말한 구간 중 어디가 달라졌는가. **원인을 단정하지 말고 관측만 적는다** |
| **2d** | 큰 모델의 소요 시간이 **감당할 만한가** | §4.1의 값을 함께 본다. *"정확하지만 이 회의에는 못 쓰겠다"* 도 유효한 답이다 |
| **2e** | **★ 그래서 어느 것으로 쓰겠는가** | 이것이 HR-2의 판정이다. **"둘 다 못 쓰겠다"도 답이며, 그때는 모델 크기가 문제가 아니라는 뜻이다** |

> ⚠️ **붕괴 판정은 품질 판정이 아니다** (`ADR-0007` §18.6). 두 결과가 모두 붕괴를 통과했다는
> 것은 *붕괴가 아니다*까지만 말하고 *읽을 만하다*를 말하지 않는다.

### 5.4 이 결과가 무엇을 바꾸는가

| 결과 | 무엇이 따라오는가 |
| --- | --- |
| **`base`로 충분하다** | `PRODUCT-SPEC` §14.4가 UNVERIFIED로 적어 둔 *"`large-v3`가 현실적"* 이라는 서술의 첫 실측 반례가 된다. **Spec을 고치는 것은 이 문서가 아니라 그 뒤의 Task다** |
| **더 큰 모델이 필요하다** | 같은 자리에 첫 실측 근거가 생긴다. 기본값을 굳힐지는 별개의 결정이며 **앱은 여전히 모델을 강제하지 않는다** (`ADR-0007` §8.1) |
| **어느 쪽도 읽을 만하지 않다** | **모델 크기가 원인이 아니라는 뜻이다.** `SYSTEM-MAP` §5의 C-1 ~ C-5(청크 분할 · state 재생성 · 반복 차단 · VAD · 감지 개선)가 후보에서 다음 Phase의 대상으로 올라간다 |

**어느 경우에도 이 문서가 결정을 내리지 않는다.** 기록하고, 결정은 운영자가 한다.

### 9.2 어디에 적는가

- **이 문서의 §8** — Human Review 실행 기록.

- 결과가 **Runtime / Planner의 문제**로 보이면 `docs/LOOP-RUNTIME-FIELD-NOTES.md`다.
  **제품 문제를 Runtime 문제로 적지 않는다** (`CLAUDE.local.md` — Field Note Quality).
- **§8.1 · §8.2의 결과는 `A-TRANS-001`의 상태를 바꿀 수 있는 입력이다.** 그 결과가 나오면
  `ADR-0007` §16.3.1과 `SYSTEM-MAP` §7을 갱신하는 것은 그때의 Task이며,
  **이 문서가 대신 적지 않는다.**
- **§8.2의 결과는 `PRODUCT-SPEC` §14.4의 모델 서술(UNVERIFIED)에 대한 첫 실측이다.**
