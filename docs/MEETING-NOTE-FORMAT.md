# 회의록 형식 (Meeting Note Format)

> 상태: **구현됨 (Phase 5.10 · 2026-11-13)**.
> 앱의 Meeting 노트가 이 형식을 따른다 — content schema v2 (`PRODUCT-SPEC.md` §9.5).
> 그 전에 만든 노트(v1: Overview · Key Discussions · Decisions · Action Items · Open Questions)는
> 그대로 읽히고 그대로 렌더된다.

## 왜 있는가

팀이 실제로 노션에 올리는 위클리 회의록 형식이 있고, 앞으로의 회의 요약은 모두 그 형식에
맞춰야 한다. 원본 예시는 **실제 회의 내용이라 이 저장소에 두지 않는다** (GIT-WORKFLOW §7).
이 문서는 그 형식의 **구조와 규칙만** 옮긴 것이다.

## 전체 구조

```text
# [YYMMDD] <회의명>_회의록

이벤트 시간: YYYY년 M월 D일 HH:MM (GMT+9)
참석자: <이름>, <이름>, ...

# YYYY-MM-DD (요일) <회의명> 회의록

> 📌 <전사 신뢰도 안내 — 아래 §1>

- **일시**: YYYY-MM-DD (요일) [HH:MM ~ HH:MM]
- **유형**: <회의 종류> (<이번 회의의 특이사항이나 흐름 한 줄>)

---
## 🔑 핵심 요약               ← §2
---
## 🔁 지난주 액션 아이템 진행 상황   ← §3 (해당될 때만)
---
## 1. <주제>                  ← §4, 주제 수만큼
## 2. <주제>
...
---
## ✅ 액션 아이템              ← §5
---
## 🔍 확인 필요               ← §6
```

**풀 전사(원문)는 넣지 않는다.** 원문이 어디 있는지만 안내 문구에 적는다.

## 1. 머리말 · 안내 문구

- 제목의 날짜는 `[YYMMDD]` 6자리.
- 참석자를 음성만으로 확정할 수 없으면 그렇다고 적는다 (`음성 기준 추정 — 확인 필요`).
- 📌 안내 문구에 들어갈 것:
  - 녹음 길이와 자동 전사 후 정리했다는 사실
  - 이름·용어는 음성 인식 기준이라 틀릴 수 있으니 **확인 필요**를 보라는 안내
  - 소리가 작거나 말이 겹쳐 **빠진 말이 많은 구간**이 있으면 그 구간
  - 원문 전사가 있는 곳

## 2. 🔑 핵심 요약

- **번호 목록, 5~7개.**
- 각 항목은 `**굵은 한 줄 결론**: 설명` 모양.
- 날짜·금액·수치가 결론이면 굵게.
- 지시나 강조 발언은 `💬`로 시작해 굵게 — `💬 **RFP 기능을 100% 수용하는 것이 핵심**`.

## 3. 🔁 지난주 액션 아이템 진행 상황

정기 회의(위클리 등)에서 지난 액션 아이템을 점검했을 때 쓴다. 점검이 없었으면 이전 회의록의
항목 중 **이번 회의에서 실제로 언급된 것만** 짧게 적는다. 언급이 없었던 것을 추측해 채우지 않는다.

분류는 다섯 가지다.

| 분류 | 뜻 |
| --- | --- |
| **완료** | 끝났다고 말한 것 |
| **일정·방향 변경** | 날짜나 방법이 바뀐 것 — 바뀌기 전과 후를 함께 |
| **진행 중** | 하고 있다고 말한 것 |
| **진전 없음** | 아직 못 했다고 하거나, 물었는데 답이 없었던 것 |
| **회의에서 언급 없음** (이월) | 목록에는 있었으나 다뤄지지 않은 것 |

항목 모양: `- **<항목>** → <상태 설명>`

## 4. 주제별 섹션

- `## N. <주제>` 로 번호를 붙인다. 회의에서 다룬 순서보다 **주제 묶음**이 우선이다.
- 한 주제 안에서 하위 묶음이 필요하면 `**굵은 소제목**`을 쓰고 그 아래에 글머리표.
- 문장은 짧은 평서형 종결(“~함”, “~예정”, “~하기로 함”)로 쓴다.
- 표시 기호는 의미가 정해져 있다.

| 기호 | 쓰는 곳 |
| --- | --- |
| `💬` | 결정권자의 지시·피드백·강조 발언. 내용은 굵게 |
| `⚠️` | 문제·위험·주의 |
| `→` | 그래서 무엇을 하기로 했는지 |
| `STT상 ‘…’` | 음성 인식이 그렇게 들었으나 확신할 수 없는 고유명사·숫자 |
| `(STT 기준)` | 문장 전체가 인식 결과에 기대고 있을 때 |

- 금액이 엇갈리거나 확신할 수 없는 구간은 **옮기지 않고 맥락만 적고**, 전사의 시각을
  `> 인용` 블록으로 안내한다.
- 비교가 핵심인 내용(일정 단계, 후보 비교 등)은 표를 써도 된다.

## 5. ✅ 액션 아이템

- 맨 위에 안내 인용문: 담당자는 맥락으로 추정한 경우가 많으니 「담당 확인」 항목은 직접
  지정하라는 것, 날짜가 나오지 않은 항목은 「일정 확인」으로 두었다는 것.
- 기간으로 묶는다: `### 이번 주 (~M/D 요일)` · `### 다음 주 이후` (회의 성격에 따라 기간
  이름은 바꿔도 된다).
- 항목 모양:

```text
- [ ]  **<할 일>** (<보충 설명>) — <담당> · 📅 <날짜>
```

  - 담당을 모르면 `담당 확인`, 추정이면 `<이름>(추정)`.
  - 날짜가 안 나왔으면 `📅 일정 확인`. 전사로만 들은 날짜는 `📅 11/11 (STT 기준)`.
  - 결과나 후속은 다음 줄에 `→ <결과>` 또는 하위 글머리표로 단다.
- 회의에서 나오지 않은 할 일을 만들어 넣지 않는다.

## 6. 🔍 확인 필요

사람이 확인해야 하는 것을 모은다 — 안내 문구가 이곳을 가리킨다.

- 참석자·호칭이 불확실한 것
- 누가 한 말인지 불분명한데 담당이 걸린 발언 (전사 시각과 함께)
- 고유명사·숫자 중 인식이 의심되는 것 (`STT상 ‘…’` → 무엇으로 읽었는지)
- **반복 인식·깨진 구간** — 내용으로 읽으면 안 되는 구간을 시각과 함께. 예: 같은 문장이
  여러 번 반복된 것을 일정(“매주 ○요일”)으로 오해하지 않게 짚어 준다

## 하지 않는 것

- 풀 전사를 붙이지 않는다.
- 전사에 없는 결정·담당·날짜·수치를 지어내지 않는다.
- 불확실한 것을 확실한 것처럼 쓰지 않는다 — 표시(`STT상`, `추정`, `확인 필요`)로 드러낸다.
