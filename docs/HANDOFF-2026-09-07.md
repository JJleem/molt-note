## 3. 오늘 발견된 가장 큰 남은 문제 — 무음 구간 환각

**[관측된 사실]** 위 전사의 `00:57 ~ 01:07` 약 10분 구간이 통째로 환각이었다.

```text
00:57:03 ~ 00:57:56   "멈추린 곳이."          약 45회 (미리보기 기준)

                      (내용은 개인 녹음이므로 옮기지 않는다 · GIT-WORKFLOW §7)
```

**`한글자막 by 한효정`은 2026-09-07에 51분 녹음을 통째로 날린 바로 그 문장이다**
(ADR-0007 §18.1).

**[유력한 설명]** whisper는 YouTube 자막으로 학습했고, 무음/저에너지 구간에서 디코더가
학습 데이터의 자막 상투구를 뱉는다. 말이 있는 구간은 정상이고 조용한 구간만 무너진다는
관측이 이 설명과 맞는다.

**[미검증]** 그 10분 구간의 실제 입력 레벨은 아직 측정하지 않았다. `ADR-0003 §16.1`의
레벨 측정을 구간별로 돌리면 답이 나온다. **측정 전에 원인을 단정하지 않는다.**

### 고칠 수단은 이미 의존성 안에 있다

`whisper-rs` 0.16.0이 노출하고 있으며 **지금 하나도 쓰지 않는다**

## 4. ⚠️ Runtime을 거치지 않은 변경이 있다

**오늘 마지막 세 가지 수정은 대화형 세션이 직접 했다.** 운영자가 시간을 이유로 그 경로를
선택했다 (2026-09-07 · `19:00` 테스트 목표).

```text
Gate         cargo build · cargo clippy · cargo test · tsc · vitest  — 전부 통과
Verifier     없음
Task 기록    없음
ADR 반영     없음
```

**`self-check`는 판정이 아니다** (`CLAUDE.local.md`). 아래 셋은 **다음 Phase가 정식으로
흡수해야 한다.**

### 4.1 UTF-8 경계에서 잘린 글자 (`transcription/chunking.rs`)

2026-09-07 실행이 `chunk 32/37: segment 2/14: Invalid UTF-8 detected in a string from
Whisper. Index: 0, Length: 1`로 죽었다. **그때까지 만든 31개 청크가 함께 버려졌다.**

원인: whisper.cpp의 segment 경계는 **토큰 경계이지 글자 경계가 아니다.** 한글은 UTF-8로
글자당 3바이트이므로 경계가 글자 한가운데 떨어지면 앞은 끝이 잘리고 뒤는 이어지는
바이트로 시작한다.

수정: `whisper.rs`가 `to_str()` 대신 `to_bytes()`로 읽고, `decode_segment_texts`가 잘린
꼬리를 다음 segment 앞으로 넘기며 디코딩한다. **lossy 변환을 쓰지 않았다** — 그러면
경계마다 글자가 하나씩 사라지고, 72분 녹음에서 그 경계는 수백 곳이다.

### 4.2 반복 차단이 실행 경로에 연결되지 않았다 (`transcription/run.rs`)

**Phase 5.8이 `block_consecutive_repeats`를 만들고 테스트까지 붙였지만 부르는 제품 코드가
없었다.** `tests/transcription_chunking.rs:49`가 그 사실을 적고 있었다 —
*"이 함수를 부르는 제품 코드는 아직 없다(모듈과 재수출뿐이다)."*

수정: 판정(`assess`) **뒤에** 차단하도록 연결했다 (ADR-0007 §20.6의 순서). 지워진 개수는
`Completed::removed_segments`로 남는다.

또한 §20.6.1의 차단은 **이어진 segment들**이 같을 때만 동작하는데, 관측된 붕괴는
**segment 하나의 텍스트 안에서** 일어났다 (`"엉덩이" × 13`). 그래서
`collapse::collapse_repeated_phrases`를 더했다 — 한도는 `MAX_CONSECUTIVE_REPEATS`를
인자로 받아 **값을 두 번 정의하지 않는다.**

### 4.3 전사 중 미리보기 (`transcription/progress.rs` · 신규)

72분 녹음이 도는 동안 화면이 보여 줄 수 있는 것이 "돌고 있다" 한 마디뿐이었고, 그래서
2026-09-07 실행은 40분을 돌고 실패할 때까지 사람이 한 글자도 보지 못했다.

지금은 조각이 끝날 때마다 문장이 화면에 쌓이고 진행률이 함께 보인다.

**경계 규칙을 지켰다** — Phase 5.8의 경계 테스트(`tests/transcription-chunking-boundary.test.ts`)가
초안을 네 군데에서 막았고, **테스트를 약화시키지 않고 코드를 고쳤다**:

```text
IPC에 "centisecond"가 노출됨          → 변환을 transcriber로 옮기고 payload는 ms만 안다
run.rs가 chunking을 알게 됨            → 전사 모듈의 공개 표면에서 받는다
chunking이 문장 정규화를 다시 구현      → collapse로 옮기고 한도를 인자로 받는다
whisper.rs의 원시 값 이관 형태가 깨짐   → 원래 형태를 되살렸다
```

진행률은 **"몇 번째 청크"가 아니라 오디오 진행 비율**이다 — ADR-0007 §20.8이
*"청크를 화면·IPC에 드러내는 것: 아무도"* 로 정했기 때문이다 (INV-9).
